## 실험 B — AI 영상 클립

- 판정: **조건부** — 시작 이미지에서 그대로 이어지는 연속 동작 컷만 가능, 동작 전환 지시는 불가. 무료 웹 경로는 수동이라 2단계 자동화에는 유료 API가 필요
- 근거(한 줄): flow_01(타이핑 지속)은 8초 내내 손·자판이 안정적이고 klein 톤·구도를 그대로 유지. flow_02(멈춤→손 떼기)는 손을 펼쳐 공중에 드는 엉뚱한 동작 후 타이핑 자세로 튀며 복귀 → 지시 불이행
- 도구·모델: Google Flow(무료 계정), Veo 3.1 Lite, image-to-video. 시작 프레임은 `A_image/klein_tone_s1_1080x1920.jpg`. 프롬프트는 `spike/B_video/seedance_prompts.md`의 초안 1·2를 Flow에 그대로 사용(Seedance용으로 썼지만 도구만 바뀜). Dreamina(Seedance)는 웰컴 무료 크레딧이 지급되지 않아 포기
- 클립당 비용: 0원. Flow 무료 50크레딧/일 중 클립당 10크레딧(2개 생성 후 30 남음 → 하루 최대 5클립)
- 생성 시간: 약 5분/클립(사용자 측정)
- 출력 사양(ffprobe 실측): 720×1280, H.264, 24fps, flow_01 7.93초(190프레임), flow_02 8.00초(192프레임), 비트레이트 1.4~1.5Mbps(낮은 편), AAC 48kHz 스테레오 — 오디오는 무음이 아니라 실제 소리(평균 -39dB, 최대 -6.7/-10.4dB). 오른쪽 아래 "Veo" 가시 워터마크(한국 계정 강제), 1080 확대 후에도 보임
- 실패율: 동작 지시 기준 1/2(flow_02). 손가락·얼굴 결함 기준 0/2
- 손가락·키보드 자판 왜곡: flow_01은 8초 전 구간 손가락 개수·관절 안정, 자판 형태 유지(각인은 klein처럼 가짜 글자지만 아웃포커스). flow_02 공중 손 구간은 흐리고 약간 반투명·부자연
- flow_02 타임라인(프레임 실측, 사용자 기술과 다른 점): 손이 들리기 시작 **약 3.4초(프레임 82)** → 펼친 손 공중 유지 약 1.5초 → **약 4.9~5.0초(프레임 118~120)에 약 3프레임(0.13초) 만에 타이핑 자세로 튀며 복귀**. 사용자 기술(3.5~5초 들어 올림, 5.4초 복귀)보다 복귀가 0.4~0.5초 이름
- 얼굴 노출 여부: 0/2
- 카메라 지시: flow_01의 푸시인은 거의 느껴지지 않을 만큼 약함(사용자 관찰과 같음). 프롬프트의 카메라 지시는 약하게만 반영됨
- 확대 화질(720→1080, 1.5배): Remotion `VideoBackground`(cover)로 확대한 프레임을 klein 원본 KenBurns와 같은 영역 600px로 잘라 비교 → klein보다 필름 그레인이 뭉개져 약간 매끈하지만 손가락 윤곽·자판 경계는 깨지지 않음. 휴대폰 시청 기준으로는 문제없는 수준. 가장 거슬리는 건 화질보다 워터마크
- Remotion 렌더(Core Ultra 7 258V): `SpikeB`(flow_01 1080×1920 확대·음소거·5초) 콜드 65초 / 웜 14초, `SpikeBCompare`(A KenBurns | B Veo | 007 Pexels, 3240×1920) 콜드 42초 / 웜 39초. 같은 번들의 웜 SpikeA 14초 → **SpikeB는 2D 이미지 씬과 같은 1.0배**. 출력 오디오 max -91dB로 음소거 확인
- 2단계에서 API로 쓴다면(공식 문서 확인, 호출 안 함, 2026-10-30):
  - **Gemini API의 Veo 3.1 Preview(Lite 포함)는 2026-10-22 종료.** 공식 문서는 Gemini Omni Flash(`gemini-omni-1.1-flash`, 유료 tier 전용, 무료 없음, 720p 약 $0.10/초)나 Google Cloud(Agent Platform/Vertex)의 GA Veo로 옮기라고 안내
  - Google Cloud 가격표의 Veo 3.1 Lite: 720p 영상만 **$0.03**, 영상+오디오 $0.05 / 1080p 영상만 **$0.05**, 영상+오디오 $0.08 (단위 "1 count" — 공식 페이지에 정의는 없지만 서드파티 자료 모두 초당으로 해석)
  - 환산(1달러=1,400원): 8초 클립 720p 영상만 $0.24 ≈ **336원**, 1080p 영상만 $0.40 ≈ **560원**. 에피소드당 연속 동작 컷 3개면 약 1,000~1,700원. 오디오는 쓰지 않으므로(나레이션만) "영상만" 단가 적용. API 경로는 가시 워터마크 없이 SynthID만 붙는지 2단계에서 확인 필요
- ③단계에 넣는다면 필요한 것: (1) **연속 동작 컷 전용**(타이핑 지속, 화면 응시 등 시작 이미지의 동작을 그대로 잇는 것). 동작 전환은 KenBurns+편집 컷으로 대체. (2) 5초로 잘라 쓰기 — 8초 생성분에서 가장 안정적인 구간 선택. (3) 무료 경로는 사람이 웹에서 생성 → 하루 5클립, 클립당 5분 수동. 자동화하려면 Google Cloud 결제 계정(고정비 0, 사용량 과금) 필요 → 도입 전 비용 승인 필요. (4) 워터마크: 무료 Flow 출력은 가시 워터마크가 있어 크롭(약 5%)이 필요하거나 API 경로 사용

## 실험 C — Remotion 3D 씬

- 판정: **쓸 만함** (단 `--gl=angle` 필수)

- 도구·모델: @remotion/three 4.0.512(remotion과 같은 버전 고정) + three 0.186.1 + @react-three/fiber 9.8.2 + @types/three 0.186.0. 설치 후 `tsc --noEmit` 통과, 기존 Episode 렌더(007 앞 10초) 정상 → 회귀 없음
- 비용: 0원
- 씬: `remotion/src/spike/SpikeC.tsx` — 파이프라인 7단계(기획→대본→나레이션→B-roll→터미널 캐스트→렌더→업로드) 블록이 14프레임 간격으로 spring 낙하하며 쌓이고 카메라가 ±0.55rad 공전. 어두운 배경 + 쿨블루 조명. 블록 글자는 3D 텍스트가 아니라 같은 카메라 행렬로 투영한 좌표에 얹는 2D 오버레이
- `--gl` 옵션별 결과(이 PC: Core Ultra 7 258V / Arc 140V). 전 옵션 렌더 성공, 결과 화면 동일. 실제 백엔드는 WebGL 렌더러 문자열로 확인:

  | `angle` (공식 권장) | **Arc 140V GPU, D3D11** | 16초 | **0.84배** |
  | `vulkan` | **Arc 140V GPU, Vulkan** | 16초 | 0.84배 |
  | (미지정, 4.0 기본 `null`) | SwiftShader(소프트웨어) | 27초 | 1.42배 |

- 렌더 시간(콜드/웜): 콜드(소스에서 직접, 번들링 포함) SpikeC angle **17초**. 번들 단독 6초. 웜(미리 만든 번들) 위 표. 참고로 SpikeA 콜드 74초는 spike 엔트리의 최초 rspack 캐시 생성까지 포함한 값이라 콜드끼리 배수(0.23배)는 의미 없음 → **웜 기준 0.84배가 대표값**
- 실패율: 0/8 (콜드 1 + 웜 6옵션 + 2D 기준 1). Remotion 종료 시 "Was not able to close puppeteer page" 경고는 기존 렌더에도 뜨는 무해한 로그
- 주의: 공식 문서는 Remotion 4.0에서 three.js가 기본 렌더러로 동작하지 않는다고 하지만, 이 PC에서는 기본값도 SwiftShader로 폴백해 화면은 나왔음. 다만 1.7배 느리고(27초 vs 16초) 셰이더·후처리가 늘면 격차가 벌어질 것
- ③단계에 넣는다면 필요한 것: (1) 3D 씬 렌더에 `--gl=angle` 명시 — `remotion.config.ts`의 `Config.setChromiumOpenGlRenderer("angle")`가 공식 권장이지만 기존 2D 렌더에도 영향이 가므로 2단계에서 render.ts에 반영할지 결정(이번엔 미변경).
