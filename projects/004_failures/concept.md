# 004_failures — concept.md

## 한 줄 컨셉
"이 자동화 파이프라인, 사실 세 번 실패했어요" — 002(WHAT)·003(HOW)에 이어지는 메타 시리즈
3번째 편. 이번엔 "비하인드/시행착오"를 다룬다.

## 핵심 메시지
자동화 파이프라인도 처음부터 매끈하게 되는 게 아니라, 실패 → 원인 파악 → 우회/수정을
거쳐 지금 모습이 됐다는 것. 실제로 문서(`docs/002_test_리뷰_개선백로그.md`,
`docs/remotion_트레이드오프_claudecode인계.md` 항목 15)에 기록된 진짜 사건을 그대로 쓴다 —
지어낸 에피소드가 아니라 실제 개발 로그.

## 다루는 실패 3개 (전부 검증된 실제 사건)
1. **화면 캡처 3연속 실패 → 보안사고**: vhs(행), PowerSession(TTY 미연결) 다 실패하고
   ffmpeg gdigrab을 시도했다가 사용자의 실제 데스크톱을 그대로 캡처하는 사고가 남 →
   이후 에이전트의 화면 캡처를 전면 금지하고 cast-builder(실제 명령 출력 + 합성 타이밍)로
   완전히 다른 접근을 택함.
2. **Playwright Studio 녹화 버튼 버그**: `title="Play"` 속성이 DOM에 분명히 있는데도
   `locator().click()`이 recordVideo 컨텍스트에서만 계속 타임아웃 — 원인은 못 밝혔지만
   좌표 직접 클릭으로 우회.
3. **얼어붙은 프레임 버그**: Studio 녹화 결과물의 앞 ~4초가 항상 정지 화면이라 짧은 씬에서
   티가 났음 → ffmpeg 트림(재인코딩 필요, 스트림 복사는 빈 화면만 나옴)으로 해결.

## 타겟 러닝포인트
"자동화 파이프라인 = 완벽하게 설계해서 한 번에 굴러가는 것"이라는 오해를 깨는 것.
실패-수정 사이클 자체가 자동화 구축의 정상적인 일부라는 실감을 주는 것.

## 톤
002/003과 동일한 정보성 쇼츠 톤이되, 이번엔 "좌절 → 디버깅 → 해결"이라는 감정선이 있어
b-roll(사람의 표정·동작)이 자연스럽게 붙는 편.

## 씬별 비주얼 소스 배정 (b-roll 우선 정책 첫 적용, 2026-08-23 정책 갱신 반영)
| 씬 | 타입 | 내용 | 비주얼 소스 |
|---|---|---|---|
| 1 title | title | 훅: "사실 세 번 실패했어요" | Pexels b-roll(답답해하는 사람) |
| 2 talkingPoint | 실패①: 화면 캡처 3연속 실패 → 보안사고 | Pexels b-roll(모니터 보며 타이핑) |
| 3 code | 사고 후 cast-builder로 전환한 순간(실제 명령 캡처) | cast-builder 터미널(구조적 예외, 유지) |
| 4 talkingPoint | 실패②: Studio 녹화 버튼 버그 | Pexels b-roll(야간 디버깅) |
| 5 talkingPoint | 해결: 좌표 클릭으로 우회 | Pexels b-roll(안도/완성 순간) |
| 6 outro | 마무리 | pulse 모션그래픽(유지) |

Studio 녹화(Playwright)는 이번 편에는 쓰지 않음 — 정책상 선택 사항으로 낮아졌고, 이번
소재(실패담) 자체가 b-roll과 더 잘 맞음.
