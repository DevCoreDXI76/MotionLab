## 2. script.json 스키마 변경안

원칙: **추가만 한다(모두 optional)**. 001~007의 script.json은 수정 없이 새 스키마를 통과해야 한다. `visual.kind`가 없으면 지금과 똑같이 동작한다(assetPath 있으면 이미지/영상, 없으면 모션그래픽).

### 2.1 scene.visual (확장)

```jsonc
"visual": {
  // ── 기존 (그대로) ──
  "cue": "terminal",            // 모션그래픽 variant
  "assetPath": "projects/008_x/images/scene-2.jpg",  // 렌더가 실제로 읽는 유일한 경로
  "focal": "center",

  // ── 신규: 대본 단계가 쓰는 "의도" ──
  "kind": "aiImage",            // "pexels" | "aiImage" | "three" | "existingClip" | "motion"
  "query": "hands typing on laptop keyboard close up",   // pexels: 영어 검색어
  "prompt": "hands resting on a laptop keyboard at night", // aiImage: 장면 묘사(스타일 접미사는 코드가 붙임)
  "clipId": "flow_01",          // existingClip: templates/existing_clips.json의 id
  "diagram": {                  // three: 3D 다이어그램 데이터
    "preset": "stack",
    "labels": ["기획", "대본", "나레이션", "비주얼", "렌더", "업로드"],
    "highlight": 3,
    "accent": "#2f7bff"
  },

  // ── 신규: 프로바이더가 쓰는 "출처" (백로그 1) ──
  "source": {
    "provider": "cloudflare-workers-ai",   // | "pexels" | "existing-clip" | "remotion-three" | "motion"
    "model": "@cf/black-forest-labs/flux-2-klein-4b",
    "prompt": "<스타일 접미사까지 붙은 최종 프롬프트>",
    "seed": 20261113,
    "pexelsId": null, "photographer": null, "pageUrl": null, "query": null,
    "clipPath": null, "trim": null,
    "candidates": [ { "file": "...", "seed": 1, "verdict": "pass", "reasons": [] } ],
    "selectedBy": "auto-vision",           // | "auto-rule" | "fallback" | "only-candidate"
    "fallbackFrom": null,                  // 예: "aiImage" (aiImage 실패 → pexels로 내려온 경우)
    "neuronsEst": 312.6,
    "generatedAt": "2026-11-13T12:00:00Z"
  }
}
```

- `kind`·`query`·`prompt`·`clipId`·`diagram`은 **대본 생성 단계가 채우는 의도**, `source`는 **프로바이더가 채우는 결과**다. 사람이 다시 볼 때 "무엇을 원했고 무엇이 들어갔는지"가 한 파일에 남는다(007은 쿼리가 gitignore된 `*.credit.json`에만 있었음).
- `visual`은 현재 `additionalProperties: false`라 위 필드를 명시적으로 추가한다. `source`는 프로바이더별로 필드가 달라 `additionalProperties: true`로 느슨하게 둔다.
- `kind`별 필수 필드(aiImage→prompt, pexels→query 등)는 JSON Schema `oneOf` 대신 **코드 검증(`validateVisualIntent`)**으로 확인한다. 이유: `claude -p --json-schema`가 유니언·oneOf를 어디까지 받는지는 2026-08 계획서에서도 "확인 못 함"으로 남아 있다(`docs/superpowers/plans/2026-08-15-...md` 1119행). 평평한 optional 필드가 생성 실패 위험이 가장 낮다.
- **D1 확정(B)**: 3D는 visual kind가 아니라 새 씬 타입 `diagram`이다. 따라서 `visual.kind`는 `"pexels" | "aiImage" | "existingClip" | "motion"`이고, 위 예시의 `visual.diagram` 대신 diagram 씬의 `props`에 `{ heading, preset: "stack", labels, highlight?, accent? }`를 둔다.

### 2.2 code 씬 props (백로그 6)

```jsonc
"props": {
  "language": "bash",
  "code": "npx vitest run scripts/lib/pexels.test.ts",
  "caption": "회귀 테스트 통과 확인",
  "commands": [
    { "display": "npx vitest run scripts/lib/pexels.test.ts", "argv": ["npx", "vitest", "run", "scripts/lib/pexels.test.ts"], "cwd": "remotion" }
  ],
  "cast": { ... }   // 기존 그대로, cast 단계가 채움
}
```

- `cwd`는 `"root" | "remotion"` 두 값만. 절대경로 금지.
- 해석 순서: `props.commands` → (없으면) 기존 `SCENE_COMMANDS[projectId][sceneId]` → (둘 다 없으면) 실패. 002~007은 계속 상수에서 읽으므로 결과 불변.

### 2.3 대본 생성용 스키마 분리

`claude -p --json-schema`에는 **작성 전용 스키마**(`templates/script_authoring_schema.json`)를 넘긴다: 전체 스키마에서 `durationMs`·`audioPath`·`visual.assetPath`·`visual.source`·`props.cast`를 뺀 것. 생성 후에는 기존처럼 전체 스키마(`script_schema.json`)로 다시 검증한다. 지금은 프롬프트로 "durationMs·audioPath는 생략하라"고 부탁하는 방식이라, 모델이 넣으면 그대로 통과한다.

## 3. 대본 프롬프트 템플릿 변경안

`templates/script_prompt_template.md`를 수정하되 `{{TOPIC}}` 경로(001_sample 방식)는 그대로 동작하게 둔다. 신규 변수와 지시:

1. **입력**: `{{CONCEPT}}` — concept.md 전문. "concept.md에 없는 사실·수치는 지어내지 말 것. 나레이션의 숫자는 concept.md에 있는 것만."
2. **씬 구성**: 기존 규칙(title → talkingPoint ≤2 → code? → outro, 400~550자) 유지. 008용으로 `talkingPoint` 최대 개수를 4로 완화할지는 M1에서 007 길이(54초) 기준으로 확인.
3. **비주얼 배정 규칙**(씬마다 `visual.kind` 필수):
   - `aiImage` — 감정 비트·분위기 컷. 손·화면·사물만, 정적 포즈("타이핑", "손을 올려둔") 한정, 화면 속 글자를 읽혀야 하는 장면 금지. `prompt`는 장면 묘사만 영어로; 스타일(야간 저조도, 35mm, only hands, no people, screen out of focus, no text)은 코드가 고정 접미사로 붙인다 → 편 간 톤 일관성을 모델에 맡기지 않음.
   - `pexels` — 실제 움직임이 필요한 컷. 영어 `query`, "close up", "hands" 포함 권장, face/portrait/selfie 금지.
   - `diagram` 씬(D1) — 구조·단계·흐름 설명 컷. `props.labels` 3~7개, 각 8자 이내 한국어.
   - `existingClip` — `{{EXISTING_CLIPS}}`(registry id·설명 목록)에 있는 것만.
   - `motion` — 위가 모두 부적절할 때.
   - 하한·상한: aiImage **2~4씬**(하한은 AI 비주얼 하한선, 상한은 Cloudflare 할당 §5), diagram **1~2씬**, existingClip ≤ 1씬. 하한은 프롬프트에 명시하고 `validateVisualIntent`에서도 검사한다(미달이면 §5.2 "스키마·의도 검증 실패"와 같이 재생성).
4. **code 씬 명령**: `{{ALLOWED_COMMANDS}}`(허용 목록, §4 백로그 6)에 있는 형태만. 출력 내용(통과 건수 등)을 나레이션에서 단정하지 말 것 — 명령 실행 결과는 생성 시점에 모르기 때문.
5. **훅 규칙·문장부호 규칙·props 형식**: 기존 그대로.

## 5. 오케스트레이터 · 실패/폴백 규칙

### 5.1 단계와 상태

```
produce.ts 008_x
  0 preflight   concept.md 존재, secrets 파일 존재(값은 읽기만), ffmpeg, claude CLI, YouTube 토큰 갱신 가능 여부,
                Cloudflare 오늘 잔여 neuron, 디스크 — 하나라도 실패하면 비싼 단계 전에 중단
  1 script      claude -p (concept.md) → 작성 스키마 → 전체 스키마 + validateVisualIntent
  2 cast        code 씬 props.commands 실행 → props.cast
  3 narration   EdgeTTS + duration 역주입
  4 visuals     씬별 provider + 폴백 체인 → assetPath·source
  5 render      remotion render (+--gl=angle 조건, D3) → loudnorm → metadata.txt → thumbnail.png
  6 upload      py scripts/youtube_upload.py --project projects/008_x   (privacy 인자 전달 안 함 = private 고정)
  7 report      projects/008_x/log.md "자동 실행 기록" 섹션 갱신
```

- 상태 파일 `projects/<id>/pipeline_state.json`: 단계별 `{status, startedAt, finishedAt, attempts, fallbacks[]}`. 같은 명령을 다시 실행하면 완료된 단계는 건너뛴다(입력 해시가 같을 때만). `--dry-run`은 6을 건너뛴다.
- 7은 **실패해도 반드시 실행**(finally). 기록 항목: 단계별 결과·소요·재시도 횟수·폴백 내역·neuron 사용량·업로드 URL·**사람 개입 필요 여부**.
- "사람 개입" 판정 규칙(자동 기록): 오케스트레이터가 스스로 해결하지 못하고 종료한 경우 = 개입 1건(사유와 함께 log.md에 "⚠ 사람 개입 필요"). 자동 재시도·폴백으로 넘어간 것은 개입이 아님("자동 폴백"으로 별도 기록). 사람이 파일을 고치거나 단계를 골라 재실행하면 그 자체가 개입이므로, 재실행 시 `--from`이 쓰이면 log.md에 개입으로 남긴다.

## 8. 결정이 필요한 항목

### D1. 3D 씬을 어디에 놓나
- A. `visual.kind: "three"` — 기존 씬(title/talkingPoint)의 CentralVisual 띠 안에 3D. 씬 타입 불변.
- B. **새 씬 타입 `diagram`** — 전체 화면 3D + 상단 heading + 자막. sceneRegistry에 한 줄 추가.
- C. 둘 다.
- **추천: B.** 실험 C는 1080×1920 전체 화면, 고정 카메라에서 라벨 투영을 맞춘 것이다. 띠(가로로 넓고 높이가 가변)에 넣으면 카메라·투영을 다시 맞춰야 하고, 7단 블록이 작아져 라벨이 안 읽힌다. B는 레지스트리 추가뿐이라 기존 편 영향이 없다. 이 경우 스키마 `scene.type` enum에 `diagram`, `visual.kind`에서 `three`는 빠지고 diagram 데이터는 `props`로 간다.

### D2. 후보 자동 선택의 판정기
- A. **Claude 비전 (`claude -p` + Read 도구 허용으로 이미지 파일 읽기)** — 구독 한도 안, 1단계 검수 기준을 거의 그대로 루브릭화 가능. 현재 `generateScript`는 `--allowedTools ""`라 이미지를 못 읽는다 → 판정 전용 호출에 `--allowedTools Read` + 이미지 절대경로 + 구조화 출력(`--json-schema`) 사용. **실제로 되는지는 아직 미검증** — M2 첫 작업으로 이미 판정이 끝난 klein 9장(manifest.json의 사람 review가 정답지)에 돌려 일치율을 잰다. **합격선(확정, 비대칭)**: 결함 통과(사람이 탈락시킨 손 왜곡·얼굴 노출 이미지를 통과시킴) **0건**, 정상 이미지 오탈락 **2건 이하**. 미달이면 C(픽셀 규칙) + aiImage 2씬 이하로 축소.
- B. Cloudflare Workers AI 비전 모델(무료 neuron 사용) — 같은 할당을 이미지 생성과 나눠 쓰게 되고, 판정 품질 미확인.
- C. 규칙만(픽셀 통계로 흰 테두리·해상도 + OpenCV 얼굴 검출) — 손 왜곡·가짜 글자는 못 잡음. 탈락률 ~1/3 중 상당 부분을 놓쳐 ⑦에서 걸릴 위험.
- **추천: A, 실패 시 C + "aiImage 씬을 2개 이하로 줄이고 나머지 Pexels"로 축소.** B는 할당 경쟁 때문에 마지막 대안.
- 참고: Claude 비전 판정에 이미지를 보내는 건 사용자의 Claude 구독 안에서의 처리이고 외부 공개가 아니다. 이미지는 AI 생성물(얼굴·민감정보 없음)뿐이다.

### D3. `--gl=angle` 적용 범위
- A. `remotion.config.ts` 전역 — 001~007 재렌더에도 적용, 2D 결과가 바뀔 수 있음(실험 C는 2D에 angle을 적용해 비교하지 않음).
- B. **`render.ts`가 script.json에 3D 씬이 있을 때만 `--gl=angle` 추가.**
- C. 항상 render.ts에서 추가하되 2D 회귀(§7-4 SSIM)로 확인 후 결정.
- **추천: B.** 기존 편 결과 불변이 절대 규칙 6이고, 3D 없는 편은 이득이 없다. Studio 미리보기는 기본 백엔드로도 화면은 나온다(실험 C, SwiftShader 폴백).

### D4. Pexels 키 위치
- A. **`secrets/pexels_api_key.txt`로 옮기고 `remotion/.env` 읽기 제거.** (키 파일 이동은 M1에서 내가 수행, 값은 출력하지 않음)
- B. secrets/ 우선, 없으면 `.env` 폴백(호환).
- C. 현행 유지(규칙 3 예외로 문서화).
- **추천: A.** 규칙 3을 문장 그대로 지키는 유일한 안. `.env`는 `.gitignore`에 있어 노출 위험은 같지만 "키는 한 곳" 원칙이 단순하다.

### D5. 오케스트레이터가 `youtube_upload.py`를 호출해도 되나
현재 docstring이 "다른 스크립트가 자동 호출하지 않는다"고 명시한다. 완성 기준(비공개 업로드까지 사람 개입 없음)을 지키려면 이 정책을 바꿔야 한다.
- A. **오케스트레이터만 호출 허용, `--privacy`·`--force` 인자를 절대 넘기지 않음(코드로 고정 + 테스트).** docstring을 "오케스트레이터는 private로만 호출" 으로 수정.
- B. 오케스트레이터는 6단계 직전에 멈추고, 업로드는 사람이 명령 한 줄로 실행(= "명령 하나 실행"은 개입이 아니라는 기준에 기대는 해석).
- **추천: A.** B는 해석상 가능하지만 결국 실행 판단을 사람이 하게 되어 기준의 취지와 어긋난다.

## 10. 남은 위험

1. **`claude -p` 구조화 출력이 확장 스키마를 받는지 미검증** — M1에서 작성 스키마로 실호출 1회(구독 사용, 과금 없음). 거부되면 kind별 필드를 문자열 한두 개로 더 평평하게.
2. **Claude 비전 판정 정확도 미검증**(D2) — 정답지(klein 9장 사람 검수)가 있어 M2 첫날 판정 가능.
3. **LLM이 쓴 명령의 로컬 실행** — 허용 목록·경로 가드로 막지만, 허용된 명령이라도 출력에 민감 내용(고객사명 등 커밋 메시지)이 섞일 수 있음. `git log`는 이 저장소 한정이라 위험 낮음. 그래도 cast 출력은 log.md에 원문 저장하지 않는다.
4. **나레이션과 실제 명령 출력 불일치** — 대본은 실행 전에 쓰인다. 프롬프트에서 수치 단정을 막고, M3에서 cast 출력에 "failed"/"error"가 있으면 그 명령을 제외하는 규칙 추가.
5. **YouTube 토큰 만료** — 테스트 모드 OAuth 앱은 refresh token이 7일 후 만료될 수 있음(Google 정책). M4 전날 preflight로 확인하고, 필요하면 실전 전에 재인증(실전 실행 밖에서 하는 준비 작업으로 기록).
6. **Cloudflare 실제 사용량과 로컬 추정의 차이** — 추정식은 보수적(타일 올림)이고, Free 플랜은 초과 시 과금 없이 에러이므로 비용 위험은 없음. 에러는 폴백으로 흡수.
7. **품질 하락이 ⑦에서 걸리면 재실행이 개입으로 카운트됨** — 버퍼 2주는 이 경우용. 2곳 초과 시 완성 기준 미달로 그대로 기록한다(숫자를 맞추려고 기록을 줄이지 않음).
