# 002_test.mp4 리뷰 — 개선 백로그

*작성일: 2026-08-15 · 대상: 파이프라인 첫 테스트 렌더 (9:16, 1080×1920, 82.9초, 30fps, 씬 5개)*

## 영상 구성 (관측)

TitleScene(~16초) → TalkingPointScene "왜 자동화가 필요할까"(~20초) → TalkingPointScene "Claude Code가 하는 일"(~20초) → CodeScene(터미널 명령, ~16초) → TalkingPointScene "이렇게 얻는 것" + OutroScene(~10초). 씬 간 크로스페이드 전환은 동작함. 오디오는 전 구간 연속(무음 구간 없음), mean −20.7dB.

## 발견된 문제 (우선순위순)

1. **씬 밀도/템포**: 씬당 평균 16~17초 동안 화면 변화가 전혀 없음. 쇼츠 문법(2~4초 단위 시각 변화) 대비 매우 느림. 비트레이트 171kbps가 정적임을 방증.
2. **중앙 빈 공간**: 상단 타이틀/불릿 + 하단 자막박스 사이 화면의 약 2/3가 비어 있음. 9:16 시선 중심(중앙)이 죽어 있음. `script.json`의 `visual.cue` 필드가 렌더링에서 소비되지 않고 있는 상태로 보임.
3. **자막 싱크 없음**: 나레이션 문단 전체가 한 박스에 한꺼번에 표시. 설계문서상 TTS 생성 시 문장 단위 duration을 확보하므로 라인/구절 단위 순차 표시는 추가 데이터 없이 구현 가능.
4. **씬 내부 애니메이션 부재**: 불릿 3개가 동시에 등장. stagger 등장, 강조 애니메이션 없음.
5. **훅 약함**: 첫 씬(타이틀 카드)이 16초 지속. 쇼츠는 첫 2~3초가 승부처.
6. **타이포그래피 불일치**: 라틴 텍스트("Claude Code")가 세리프체로 렌더 — 한글 산세리프와 충돌. 폰트 fallback 누락 추정.
7. **오디오 라우드니스**: mean −20.7dB / max −6.6dB. 업로드 전 loudnorm으로 −14 LUFS 타깃 정규화 권장 (유튜브는 조용한 오디오를 올려주지 않음).
8. **길이**: 82.9초 — 현 정보량 기준 45~60초로 압축이 리텐션에 유리.

## "이미지 컷 수집" 아이디어 검토 결론

방향은 맞음(2번 문제의 해법). 단, 소스 우선순위를 다르게 제안:

- **1순위 — 파이프라인 부산물 자동 캡처**: 터미널 세션/코드/Remotion Studio/렌더링 진행 화면. 메타 콘텐츠 소재와 정합, 수집 비용 0, 저작권 문제 없음. (터미널 녹화는 vhs/asciinema 등으로 자동화 가능)
- **2순위 — 코드 기반 모션그래픽 확장**: 다이어그램/아이콘/도형 애니메이션. 1차 설계의 "코드 기반 비주얼 우선" 방침과 일치.
- **3순위 — 스톡 이미지 API** (Pexels/Unsplash 등): 일반 주제 확장 시.
- **4순위 — AI 생성 이미지**: 기존 계획대로 2차 실험 트랙.

구현 형태: 씬 타입별 **asset resolver 모듈**로 추상화 — `visual.cue`를 입력으로 받아 소스(캡처/모션그래픽/스톡/AI)를 갈아끼울 수 있게. 파이프라인 ③ 에셋 준비 단계의 확장으로 편입.
