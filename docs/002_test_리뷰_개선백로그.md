**① Remotion Studio 동작 화면 — Playwright 페이지 녹화 (무료, 자동화 가능, 권장 1순위)**
- Playwright의 `recordVideo`는 **에이전트가 직접 띄운 브라우저 페이지의 뷰포트만** 기록한다 — 데스크톱 캡처가 아니므로 항목 15 위반이 아님(캡처 범위가 구조적으로 한정됨).
- Remotion Studio는 localhost 웹앱 → Playwright로 열고 재생/타임라인 스크럽/props 조작을 스크립트로 연출하며 녹화 → webm을 에셋으로 투입.
- "Remotion이 실제로 동작하는 화면" 요구를 직접 충족. 렌더 진행률 등 터미널 쪽은 cast-builder가 이미 커버.
- 규칙: 로그인된 서비스(claude.ai 등)는 녹화 금지 — 파이프라인이 띄운 로컬 앱만.

**② 실사 b-roll — Pexels Video API (무료, 자동화 가능, 권장 2순위)**
- 무료 API, 상업적 사용 가능·저작자표시 불요 라이선스. 세로(portrait) 필터 지원.
- `visual.cue`에 `broll: {keywords: [...]}` 추가 → API 검색·다운로드 → `OffthreadVideo` 풀블리드 배경. (실제 구현은 스키마 필드가 아니라 `generate-broll.ts <project> <scene> "keywords"` CLI 인자 방식으로 확정됨 — 2026-08-16 v5 작업 시 결정.)
- 용도: **2026-08-23부로 백본 비주얼로 승격** (아래 "정책 갱신" 참고) — 원래는 "배경 분위기용 1~2컷, 백본은 실물 캡처"로 한정했었으나, 실사용 피드백에서 터미널·Studio 녹화보다 b-roll 쪽이 선호되어 뒤집힘.

**③ AI 영상 생성 — 실험 트랙 개시 (유료, 훅 전용 1컷부터)**

## v5 리뷰 (56.4초) — 2026-08-23

**작업 범위**: v4의 "비주얼 단조로움" 피드백에 대응해 ①+②를 검증. 착수 전 확인해보니 ②(Pexels b-roll)는 이전 세션(커밋 `85d58b7`)에서 이미 완성돼 `scene-2-problem`에 라이브 적용까지 끝나 있었음 — 이번엔 손대지 않고 유지. 실제 신규 작업은 ①뿐이었음: 그 커밋이 남긴 `studio-demo.mp4`는 실물이었지만 이를 만든 Playwright 스크립트 자체가 리포에 없어(일회성 세션 산출물, 재현 불가) `remotion/scripts/generate-studio-capture.ts` + `scripts/lib/studioServer.ts`를 신규 작성 → `scene-3-whatitdoes`에 재적용.

**구현 방식**: `npx remotion studio --props=<script.json> --port=7788 --no-open`을 파이프라인이 직접 백그라운드로 띄우고, 그 로컬 URL만 Playwright로 열어 실제 002_test 대본(제목→불릿→b-roll→코드 순 재생)이 흐르는 걸 17초 녹화. 항목 15 예외(에이전트가 직접 띄운 페이지의 뷰포트만 기록, 데스크톱·창 캡처 아님)를 그대로 따름. 산출물은 mp4 변환 없이 webm 그대로 사용(`assetKind.ts`가 이미 webm을 지원 — 불필요한 재인코딩 생략).

**막힌 점**: Studio의 Play 버튼이 `title="Play"` 속성을 가진 게 DOM 덤프로 확인됐는데도 Playwright의 `locator().click()`이 `recordVideo` 컨텍스트에서만 30초 타임아웃으로 계속 실패. 원인은 못 밝혔지만(프리뷰 캔버스의 전역 포인터 이벤트 처리와 상호작용 추정), 뷰포트 픽셀 좌표를 직접 클릭(`page.mouse.click(391, 660)`)하는 방식으로 우회해 해결 — 이 좌표는 이 프로젝트의 Studio 레이아웃·뷰포트(1000×900)에 맞춰 튜닝된 값이라 Remotion 버전이 바뀌면 재조정 필요.

**육안 검토**: v5 렌더에서 `scene-3-whatitdoes` 프레임을 확인한 결과, 실제 Studio UI(타임라인, 재생 컨트롤, 파형, 자막 오버레이가 다 보이는)가 배경으로 깔리고 그 위에 "Claude Code가 하는 일" 불릿이 겹치는 구도가 나옴 — "Remotion으로 씬 렌더링" 나레이션과 화면 내용이 정확히 맞아떨어지는 메타적 효과까지 생김. v4의 "다크 터미널 일변도" 문제에 비해 톤 다양성 체감 개선 뚜렷: 씬2(b-roll 인물 사진), 씬3(Studio 녹화), 씬4(cast-builder 터미널)가 서로 다른 소스로 갈려 한 편 안에서 비주얼 반복이 사라짐.

**다음 판단(③ AI 영상 생성 실험) 참고용 메모**: ①+②만으로 "터미널 일변도" 문제는 충분히 해소된 것으로 보임 — ③(AI 영상 생성)의 필요성은 "톤이 못 채우는 특정 컷(훅 등)이 남아있는가"로 재평가할 것. 이번 라운드에서는 그런 갭이 뚜렷이 보이지 않아, ③ 착수는 급하지 않다는 게 잠정 결론.

## 정책 갱신 — 비주얼 소스 기본값을 b-roll 우선으로 전환 (2026-08-23)

**피드백**: v5 방식(Studio 녹화)을 실제로 003_pipeline까지 적용해본 뒤 사용자 판단 — "파이프라인은 잘 만들어졌지만 이미지 컷 자체는 여전히 맘에 안 든다. 터미널·Studio 녹화 화면보다 실제 상황의 이미지 컷(Pexels 실사 b-roll)이 낫다." v4~v5에서 "실물감 있는 캡처"를 목표로 밀었던 방향(①Studio 녹화 최우선, ②b-roll은 배경 분위기용 보조)이 실사용에서는 뒤집힌 것.

**확정 정책 (004부터 적용, 002/003은 소급 재작업 안 함)**:
- `title` / `talkingPoint` / `outro` 씬: **기본값 = Pexels b-roll**(씬 내용에 맞는 키워드로 검색). 자연스러운 실사 매칭이 없는 순수 개념 씬(예: 아웃트로 CTA)만 예외적으로 모션그래픽(pulse 등) 유지.
- `code` 씬: 컴포넌트 구조상 배경 영상을 못 받음(고정 터미널 UI) — cast-builder 터미널 그대로 유지, 이번 정책 변경의 예외.
- Studio 녹화(Playwright, `generate-studio-capture.ts`): 도구는 유지하되 "매 편 최소 1컷 필수"에서 빠짐 — Remotion이 실제로 동작하는 모습을 보여줘야 하는 특정 순간에만 선택적으로 쓴다.
- ①(Studio 녹화)을 "권장 1순위"로 명시했던 위 "에셋 소스 확장 3안"의 우선순위는 이 정책으로 대체됨: **b-roll이 1순위, Studio 녹화는 선택 사항.**
